# Cardybara beta privacy notice Effective 2026-11-11. Maintainer contact: https://github.com/stl00/Cardybara/issues (general questions only; never post account data or keys). This notice describes the beta implementation; a final publisher/store declaration is still required before store submission. ## Local data The wallet can store card product names, masked tails, balances, billing fields, point observations, source dates, limited financial-page evidence, manual benefit usage and fee records. The extension uses local Chrome storage; wallet pages also use origin-local browser storage/IndexedDB for ledgers. The bundle starts empty and contains no developer account snapshot. Cloud browser sync is not used by the application. Collection runs on supported bank pages in an existing user session. The reader does not read password values, cookies or authentication codes. Login and bank-required approval happen on the bank's own site. The connector does not pay, transfer money, redeem rewards, activate offers or change bank settings. Page structure, account association and partial dates can make collection incomplete. ## Assistant and AI card recognition The assistant is optional. In this build it works through the Cardybara hosted service with an invite code the user enters; nothing is sent until a code is saved and Chrome's permission prompt for the service is allowed. Chat text, the public card and benefit information the assistant needs, and the answers of its read-only wallet tools go through the Cardybara service to the AI model it uses. The service does not store chat content; it records only the invite code's id, time, usage and status. Bank balances and statements are not sent to the Cardybara service, and AI completion of bank pages is off in the beta. Card recognition, when turned on, sends an unrecognised card's bank, region and name (no last digits or amounts). The invite code is stored in the extension's local storage only and is never written to backups, logs or diagnostics. ## Reminders Bill and benefit reminders are optional and off by default. Turning them on asks Chrome for notification permission. Reminders are decided on this device. So that they can arrive with the wallet page closed while Chrome is running, the wallet page saves a short plan in the extension's local storage for its background worker: reminder ids, card and benefit names, dates and notification wording, and a bill amount only if the user asks for amounts. Reminders show a card or benefit name, and show an amount only if the user asks for that, because notifications can appear on a lock screen. The plan is replaced whenever the wallet page syncs and removed when reminders are turned off. Reminder settings and a list of reminders already shown stay in local browser storage, and uninstalling the extension removes them. Nothing is sent to a server. ## Retention, exports and deletion Local readings/ledgers remain until the user clears them or removes the relevant browser origin/extension. Task and evidence state is bounded and may be replaced during later runs. Exporting creates a sensitive local file under the user's control. Clearing the extension does not necessarily clear a separate website-origin wallet or exported files. Uninstalling may delete extension data; back up first. No advertising, analytics telemetry or sale of data is implemented. GitHub CI uses synthetic/public fixtures only and receives no bank login or model credential. The assistant is not entirely local: its chat is processed by an AI model through the Cardybara service, as described above.
