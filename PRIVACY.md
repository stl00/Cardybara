# Cardybara alpha privacy notice

Effective 2026-10-29. Maintainer contact: https://github.com/stl00/Cardybara/issues (general questions only; never post account data or keys). This notice describes the alpha implementation; a final publisher/store declaration is still required before store submission.

## Local data

The wallet can store card product names, masked tails, balances, billing fields, point observations, source dates, limited financial-page evidence, manual benefit usage and fee records. The extension uses local Chrome storage; wallet pages also use origin-local browser storage/IndexedDB for ledgers. The bundle starts empty and contains no developer account snapshot. Cloud browser sync is not used by the application today; the optional account sync described below is on by default once you sign in to an account (signing in is the consent point), and you can turn it off at any time.

Collection runs on supported bank pages in an existing user session. The reader does not read password values, cookies or authentication codes. Login and bank-required approval happen on the bank's own site. The connector does not pay, transfer money, redeem rewards, activate offers or change bank settings. Page structure, account association and partial dates can make collection incomplete.

## Optional model processing

Cloud parsing is optional and requires configured permissions and consent. When enabled, selected redacted financial excerpts may be sent to a chosen model service, including DeepSeek or Gemini through the configured route. Redaction is best effort and the excerpts remain sensitive. Review the consent UI and do not enable cloud parsing unless you accept that transfer.

The conversational assistant uses the Cardybara hosted service, with no invite code: chat content and card-type recognition then pass through the Cardybara gateway to the model provider (DeepSeek) and are not stored by the gateway; model-assisted bank parsing is off in that mode, so bank figures never go through the gateway, which logs only the time, route, token counts and status. To enforce a per-network daily limit, the gateway keeps a salted hash of the network address (never the address itself) for that UTC day only. The assistant can be turned off in Settings → AI service, and then nothing is sent. With an own key instead, requests go straight from the extension to the provider. See docs/GATEWAY.md.

The conversational assistant uses the configured local proxy to send chat text and necessary public card/benefit information and explicit manual benefit marks to DeepSeek. Its read-only tools do not expose bank balances or card numbers. It has no included shared API key. The local proxy key is stored in the user's private .env.local; direct-parser keys, when configured through the extension, are session-scoped. The optional loopback proxy is HTTP restricted to the user's own machine; provider requests use HTTPS.

## Reminders

Bill and benefit reminders are optional and off by default. Turning them on asks Chrome for notification permission. Reminders are decided on this device. So that they can arrive with the wallet page closed while Chrome is running, the wallet page saves a short plan in the extension's local storage for its background worker: reminder ids, card and benefit names, dates and notification wording, and a bill amount only if the user asks for amounts. Reminders show a card or benefit name, and show an amount only if the user asks for that, because notifications can appear on a lock screen. The plan is replaced whenever the wallet page syncs and removed when reminders are turned off. Reminder settings and a list of reminders already shown stay in local browser storage, and uninstalling the extension removes them. Nothing is sent to a server.

## Web version

The web version of the wallet keeps its data in the browser where it was entered (browser storage on this device); it is not uploaded or synced to other devices unless you sign in to an account, which turns sync on by default (see below). Signed out, or with sync off, it uploads no wallet document. What it does send is the questions asked to the conversational assistant (signed in or not), with the same content described above: earlier turns of the conversation, card products, point valuations, whether each card has an annual fee date and the wallet lookups the assistant asks for; never card numbers, balances or statements. Cards and amounts in the web version are entered by hand, or, for a signed-in user, imported from US credit cards linked through Plaid (see below); bank reading exists only in the desktop Chrome extension. A browser may clear the data of a site that is not on the Home Screen, so export a backup regularly. 

## Optional account and wallet sync (web version and extension)

An account is optional. Signing in, signing up, resetting a password or signing in with a passkey turns sync on for that device by default (owner decision 2026-11-23); signing in again after turning sync off turns it back on, and the switch in the account screen turns it off at any time. Without an account, or with sync off, the wallet uploads no wallet document and works exactly as above; the assistant's questions (above) and, for a signed-in user, any Plaid connection (below) are the only other things sent. This section is the boundary the account screens must keep, and `npm run check:web` and its tests enforce it where they can.

- **What the server stores** (your email, password hash, passkey, codes and sessions once you create an account; the wallet copy only while sync is on, which it is by default after sign-in): your email address, a salted password hash (never the password), a passkey public key if you add one (never a private key), short-lived email verification codes (stored only as keyed hashes), session records, one readable copy of the wallet document (cards, statement fields you or the bank page produced, fee dates, benefit and cost records, settings), and, if you turn on web push, the push subscription and fire times.
- **What it never stores:** bank passwords, cookies, bank one-time codes, bank page contents or page evidence. These stay on the bank page in your own browser; the sync body is checked against the wallet document's fields and anything else is rejected.
- **Not end-to-end encrypted.** The copy is readable on the server so that devices can merge it. The database is encrypted at rest and every request is limited to the signed-in user's own rows. The operator, who owns the Cloudflare account that hosts the database, can technically read it; the operator does not read user rows except at a user's request for a named issue, logs keep route, status, a hashed user id and size but never wallet content or credentials, and no analytics, cookies or third-party requests are used.
- **Export and deletion.** You can export everything the server holds for you, sign out (local data stays), or delete the account, which deletes every server row for it, including sessions and passkeys, and keeps the local wallet. If you forget the password, a reset code is mailed to your email address.

## Plaid-linked US credit cards (optional)

A signed-in user of the Chrome extension or the web version may connect US credit cards through Plaid. This is off until the user adds a card. Plaid Link opens on a page of the Cardybara gateway; the bank login happens inside Plaid Link, and Cardybara never sees the bank password. Cardybara asks Plaid only for credit-card data: transactions (date, amount, merchant, category, pending status) and liabilities (balance, credit limit, last statement balance and date, minimum payment, due date, APRs, last payment). It never moves money. Unlike bank-page reading, this data is stored on the gateway (Cloudflare D1) against the user's account: the Plaid access token only encrypted, the rest readable to whoever can open the owner's Cloudflare account, as with the synced wallet. The gateway logs Plaid request ids and error codes, never amounts, merchants or tokens. "Disconnect" removes the connection at Plaid and deletes its data from the gateway; deleting the account does the same for every connection; the account export includes what was synced. Plaid processes the connection under its own privacy policy. In the web version the browser goes to the gateway's Link page in the same window and is sent back to the web version afterwards; the web version itself only receives the card figures listed above from the gateway, as the extension does.

## Retention, exports and deletion

Local readings/ledgers remain until the user clears them or removes the relevant browser origin/extension. Task and evidence state is bounded and may be replaced during later runs. Exporting creates a sensitive local file under the user's control. Clearing the extension does not necessarily clear a separate website-origin wallet or exported files. Uninstalling may delete extension data; back up first.

No advertising, analytics telemetry or sale of data is implemented. GitHub CI uses synthetic/public fixtures only and receives no bank login or model credential. Providers process opted-in requests under their own policies; Cardybara does not claim that optional cloud processing is entirely local.
